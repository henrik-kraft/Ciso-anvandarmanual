## Översikt

**Våra säkerhetskrav** är organisationens samlade säkerhetskrav i Ciso.
Kraven används för att beskriva **vilken säkerhetsnivå som ska uppnås** i olika delar av verksamheten.

Ett säkerhetskrav kan till exempel beskriva krav på:

* backup
* loggning
* kryptering
* åtkomstkontroll
* leverantörssäkerhet

Kraven används sedan för att **bedöma om objekt i modellen uppfyller organisationens säkerhetsnivå**.

## State once, measure many

Ciso bygger på principen **“State once, measure many”**.

Det innebär att ett säkerhetskrav definieras en gång och sedan kan användas för att mäta efterlevnad mot flera standarder och regelverk.

Exempel:

* ISO 27001
* NIS2
* CIS Controls
* CRA

Ett säkerhetskrav kan därför kopplas till **flera säkerhetsåtgärder i olika standarder** via *Uttalande om tillämplighet (SoA)*.

När uppfyllnaden av kravet bedöms kan organisationen samtidigt mäta sin **efterlevnad mot flera ramverk**.

## Tillämpning i modellen

Säkerhetskrav kan tillämpas på olika objekt i modellen, till exempel:

* applikationer
* infrastruktur
* platser
* organisationer
* leverantörer
* processer

Genom att ange **uppfyllnad av kravet** för dessa objekt går det att följa upp organisationens säkerhetsnivå.

## Specifikationer

Ett säkerhetskrav kan delas upp i **specifikationer**.

Specifikationer gör det möjligt att anpassa kravet beroende på exempelvis:

* informationsklassning
* systemklassning
* om personuppgifter behandlas

Exempel:

* Applikationer med hög informationsklassning kan ha **strängare krav på kryptering**.
* Leverantörer kan ha **utökade krav på säkerhetskontroller**.

## Användning i styrning och uppföljning

Säkerhetskrav används bland annat för att:

* mäta **regelefterlevnad**
* följa upp **säkerhetsnivå i system och leverantörer**
* stödja **riskhantering**
* strukturera **leverantörsuppföljning**

Genom att koppla krav till objekt i modellen får organisationen en **samlad bild av sin informationssäkerhet**.
